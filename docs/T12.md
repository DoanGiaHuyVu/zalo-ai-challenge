# T12: Restrict model-generated SQL

## Summary

Add a SELECT-only execution boundary around DuckDB, using its native parser and pinned runtime. Keep the approved **10-second SQL deadline, 1 GB memory limit and two threads**.

T12 implements query permissions and cancellation. Complete result storage remains T13; no model inference or business-answer evaluation enters this checkpoint.

## Connection and execution APIs

Add in `data_tools.py`:

```python
create_connection(*, memory_limit="1GB", threads=2)

# Context manager: the host consumes rows inside the block.
restricted_query(
    connection,
    sql,
    *,
    allowed_tables,
    timeout_seconds=10,
)
```

`create_connection` returns a caller-owned, in-memory connection with:

- External access, extension installation/autoloading, unsigned/community extensions and implicit Python replacement scans disabled.
- Empty file-access allowlists and disk spilling disabled.
- Configuration locked after initialization.

Explicit temporary pandas registrations must continue working for trusted loaders. Replace the four connection-construction sites in `solver.py` with this factory. Existing loaders retain their APIs and transaction ownership.

These settings follow [DuckDB’s security guidance](https://duckdb.org/docs/2.0/operations_manual/securing_duckdb/overview). They provide application safeguards; operating-system/container isolation remains part of the later packaging work.

## Query permissions and deadline

Validate every query before execution:

- Require nonempty SQL containing exactly one parsed SELECT statement; ordinary and recursive CTEs are supported.
- Reject unbound parameters and every other statement category, including writes, DDL, `COPY`, `ATTACH`, configuration changes, extension commands and `EXPLAIN`.
- Inspect DuckDB’s [JSON syntax tree](https://duckdb.org/docs/2.0/data/json/sql_to_and_from_json), including nested subqueries and CTEs. Do not use keyword matching as the security boundary.
- Permit physical tables only from the host-supplied `allowed_tables`, derived from loaded-table metadata and `calendar`. Respect CTE scope; reject other schemas, catalogs, system tables, views and staging registrations.
- Permit built-in scalar, aggregate and window functions marked internal and without side effects in the pinned function catalog. Additionally permit the inspected built-in macros `if`, `nullif` and `date_add`.
- Permit only `range`, `generate_series`, `unnest`, `json_each` and `json_tree` as table functions. Reject dynamic SQL, file readers, Python scans, user-defined functions and other table functions.
- Reject unsupported or unrecognized syntax structures with an actionable error rather than bypassing validation.

`restricted_query` requires an idle, correctly secured connection. It opens a read-only transaction and yields a host-only cursor. The model never receives the connection or cursor.

Start the deadline before SQL validation and keep it active through execution and row consumption. A timer calls `connection.interrupt()` on expiry. On every exit, cancel and join the timer, roll back the read-only transaction and leave the connection open. Timeout cleanup must finish before another query starts.

Raise `ValueError` for rejected input, `TimeoutError` for expiry, and preserve actionable DuckDB execution errors. Errors do not establish that a business question is unanswerable. Process-level watchdogs remain T20.
