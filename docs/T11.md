# T11: Batch loading and source provenance

## Summary

Add one loading API that can create several tables in one action and combine explicitly selected, compatible sources into a single table.

The existing loaders already support transaction-neutral ingestion. The reviewed Excel fixtures contain 22 groups with matching layouts and headers, covering 299 worksheets—useful verification cases for monthly loading.

This is the implementation plan; no files have changed.

## Loader contract

Add in `data_tools.py`:

```python
load_sources(connection, business_dir, inventory, requests)
```

Each request creates one table:

```json
[
  {
    "source_ids": ["S002", "S003", "S004"],
    "header_rows": [1],
    "first_data_row": 2
  },
  {
    "source_ids": ["S001"],
    "header_rows": [1],
    "first_data_row": 2
  }
]
```

- CSV/Excel requests require explicit layout settings.
- SQLite requests contain only `source_ids`.
- Require nonempty requests and unique source IDs across the complete call. Validate arguments and resolve every source before ingestion.
- Preserve request order and source order. Assign deterministic unused table names.
- Return `tables` containing combined schemas, counts and source IDs, plus `source_catalog` containing each source’s original identity, target table, count, column labels, layout and format-specific metadata.
- The catalog is host-held JSON metadata. No additional SQL catalog table or cache enters T11.

Existing single-source APIs retain their behavior.

## Combining and atomicity

A group must use one source format and compatible positional schemas:

- **CSV/Excel:** equal column counts and exact header-label values and types, including duplicate, empty and missing labels.
- **Excel:** matching workbook epochs.
- **SQLite:** matching original column names, declared types, primary-key metadata and ordering conventions.

Reject incompatible groups with the source ID and mismatch details. Do not rename columns, normalize headers, infer matching business meanings or combine formats automatically. Different layouts use separate requests.

Reuse the existing ingestion helpers, adding an internal append path that checks compatibility before inserting each subsequent source. Stream directly into the group’s table in 4,096-row chunks; avoid whole-source DataFrames and intermediate copies.

Preserve existing storage types and provenance:

- CSV business columns remain `VARCHAR`; Excel/SQLite remain `VARIANT`.
- Every row retains `__source_id` and its original `__source_row`.
- SQLite also retains `__source_key`.
- Source-row numbering restarts for each source. Table row order is unspecified; queries must use explicit ordering.
- Do not fill blanks, deduplicate or perform business conversions.

One transaction covers **every request**, including all combined tables. Any failure rolls back the entire call, preserves existing tables and removes staging registrations. Return the catalog only after commit. Leave the caller-owned connection open; require an idle connection.

Repeated calls create fresh tables. Cache reuse and business-lifetime management remain T20.

## CLI and tests

Add a mutually exclusive, model-free command:

```sh
.venv/bin/python solver.py \
  --load-sources train/data/biz_102 \
  --requests-file /path/to/load-requests.json
```

The file contains the request array above. Reject duplicate JSON keys, malformed requests and single-source/layout CLI flags in this mode. Use the existing restricted DuckDB configuration. Exit codes remain 0 for success, 1 for loading/input-file errors and 2 for invalid CLI combinations.

Run the existing **130 tests**, adding focused coverage for:

- Multiple requests and compatible CSV, Excel and SQLite combinations.
- Header/type/epoch/schema mismatches and malformed requests.
- Preserved values, duplicates, blanks, row references and SQLite keys.
- Failure in a later source or request rolling back earlier work.
- Cleanup after aborted inserts, existing-table preservation and connection ownership.
- Repeated calls, deterministic names and model-free CLI execution.
- Unchanged single-source loaders.
