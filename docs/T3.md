# T3: Check context fit, memory use, and runtime

## Summary

Measure whether the current Qwen3 configuration can handle the released business documents on this 16 GB Mac.

Keep the model, quantization, 16,384-token context, and generation settings unchanged. This checkpoint measures model-runtime feasibility; full harness memory and accuracy remain later checks.

## 1. Add exact prompt counting

- Extract the existing non-thinking formatter into a shared helper used by both generation and token counting.
- Add `count_prompt_tokens(model, messages)` using exactly the same template, special-token handling, and tokenizer as generation.
- Inspect all 44 businesses across train and public test. Count the complete current rulebook, business README, question, `as_of_date`, and file/sheet/table-name inventory.
- Read inventory metadata only; do not implement data loaders or answer business questions.
- Record the largest context per business and every overflow case.

Report two budgets:

| Budget | Required capacity |
|---|---|
| Mandatory input | Exact prompt tokens + 1,024 response tokens |
| Reserved working space | Mandatory input + 3,072 tokens for future instructions, tool definitions, history, and observations |

The 3,072-token allowance is a diagnostic assumption. Recheck actual complete prompts after T6 and T14. Never truncate documents to make this check pass.

## 2. Exercise the model with realistic input sizes

Add:

```sh
.venv/bin/python solver.py --config config.json --feasibility
```

Reuse the existing bounded-worker mechanism and load the model once with native GPU access.

- Select the three largest development-business contexts by exact token count, excluding the six held-out businesses.
- Run eight sequential diagnostic requests: one for each selected context, then five repetitions of the largest.
- Reset model context before every request so cached prefixes do not conceal prompt-processing cost.
- Use synthetic JSON responses, without answering the embedded business questions.
- Make one request return an array of exactly 128 ones to exercise a longer output through the same constrained-generation adapter.
- Preserve the 1,024-token output cap and 300-second per-request deadline. Bound the entire diagnostic worker to 900 seconds.

Public-test inputs receive token counting only.

## 3. Record evidence

Save `artifacts/t3-feasibility.json` and its native runtime log, including:

- Model/configuration identity and input-document hashes.
- Token counts, remaining capacity, and overflow cases.
- Per-request duration, token usage, completion status, and reset status.
- Peak process RSS, normalized to bytes.
- Native Metal model, KV-cache, and compute-buffer sizes.
- Available macOS memory-pressure and swap measurements before and after.
- Partial progress if a request fails or the worker times out.

Keep RSS and Metal allocation measurements separate because unified-memory accounting can overlap. Warn at process RSS above **12 GiB**; this is a diagnostic threshold, not a new inference limit. Background system activity must not be attributed automatically to the model.

## 4. Verify and classify

Keep all nine T2 tests passing. Add focused tests for exact token-budget boundaries, non-thinking formatter reuse, untruncated documents, memory-unit normalization, and preservation of partial results after timeout.

Classify T3 as:

- **Passed:** mandatory inputs and reserved space fit; all eight requests finish within limits; memory measurements show no stated warning.
- **Passed with concerns:** mandatory inputs fit and requests complete, but reserved space, memory headroom, or measurement availability needs follow-up.
- **Failed:** mandatory inputs overflow, a required request fails or times out, or native GPU execution cannot complete.

Confirm counted prompt tokens agree with the runtime’s reported prompt usage. Do not automatically change model settings to obtain a pass.

## Completion boundary

T3 finishes with a reproducible report and an explicit classification. It does not establish competition accuracy, NVIDIA throughput, or memory feasibility after real business tables and the complete agent loop are added.
