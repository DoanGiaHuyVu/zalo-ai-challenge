# T14: Define and validate the four agent actions

## Summary

Add strict action schemas and host-side validation in `solver.py`, matching the existing inspection, loading, SQL and result-storage APIs.

T14 defines what the model may request. Tool execution remains T15; diagnostic enforcement, answer serialization and decline handling remain T17–T19. No new dependency or model inference is required.

## Action contracts

Every action contains exactly `action`, `purpose` and `args`. The first accepted action also requires `task_spec`.

| Action | Required arguments |
|---|---|
| `inspect` | `source_ids`, `start_row`, `row_count`, using T7’s bounds |
| `load` | `requests`, using T11’s explicit grouping/layout format |
| `sql` | `query`, `kind`: `compute` or `check`; checks also require `candidate_ref` |
| `finish` — computed | `answer_type`, `result_ref`, `check_ref`, `layout`, `columns` |
| `finish` — unanswerable | `answer_type="unanswerable"`, `reason`, `evidence` |
| `finish` — abstain | `answer_type="abstain"`, `reason` |

The first-action `task_spec` contains metric, period, grain, unit, expected answer type and relevant rule references. Keep these brief; allow `"unknown"` for unresolved facts and an empty rule-reference list. Once accepted, later actions must omit it. Malformed responses do not advance this phase.

Computed finishes:

- Support `number`, `percent`, `string`, `date`, `boolean`, `list` and `table`.
- Select columns using unique, positive, **one-based positions**, preserving requested order.
- Scalar types require `layout="scalar"` and one column.
- Lists use `column_list` with one column or `row_list` with one or more columns.
- Tables use `layout="table"` with one or more columns.
- Never accept a model-supplied literal answer or self-reported successful check.

Reject unknown fields at every level. Validate nonempty text, exact primitive types, identifier-list uniqueness, increasing header rows, first-data-row relationships and duplicate sources across load requests. SQLite-shaped requests omit layout fields; compatibility with actual source formats remains the loader’s responsibility.

Reference existence, question ownership, successful checks and actual output shape remain runtime validations. A structurally valid finish is not yet an accepted answer.
