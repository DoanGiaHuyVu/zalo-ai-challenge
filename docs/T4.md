# T4: Validate question inputs

## Summary

Add a reusable question loader and a validation-only CLI command. No model inference or data loading enters T4.

Inspection confirmed that all **3,000 training** and **1,000 public-test** questions contain the same four string fields, have unique IDs within their split, and reference existing business READMEs.

This session remains in Plan Mode; no files have changed.

## Implementation

In `solver.py`, add `load_questions(questions_path, data_root)`, returning validated dictionaries in their original order.

Validate each JSONL record:

- Require exactly `id`, `business_id`, `question`, and `as_of_date`, all nonempty strings. Reject unexpected fields to prevent accidentally passing answer labels into inference.
- Require a real calendar date in exact `YYYY-MM-DD` format. Do not compare it with today or infer business coverage.
- Require unique question IDs within the input file.
- Resolve each business beneath the supplied data root. Reject path traversal and paths escaping that root, including through symlinks.
- Require the business directory and its `README.md` to exist. Do not inspect structured data yet.
- Preserve Vietnamese text, identifiers, dates, and record order without normalization.

Reject empty files, blank records, malformed JSON, duplicate JSON keys, and non-object records. Stop at the first error with the filename, one-based line number, and a concrete explanation.

Add mutually exclusive CLI mode:

```sh
.venv/bin/python solver.py \
  --validate-questions train/questions.jsonl \
  --data-root train/data
```

Validation runs before model configuration or initialization. Success prints a JSON summary containing status, question count, and business count; failure prints the error to stderr and exits nonzero.

Reuse the loader in the feasibility scanner while retaining its existing document hashes and business-directory coverage check.

## Verification

Add focused standard-library tests for:

- Valid Vietnamese input, preserved order, and leap-day dates.
- Missing, unexpected, empty, and incorrectly typed fields.
- Malformed JSON, duplicate keys, duplicate IDs, and empty files.
- Impossible dates and dates using an unsupported format.
- Missing businesses or READMEs, path traversal, and escaping symlinks.
- CLI success and failure without model initialization.

Run the existing 20 tests and the new tests. Validate both released splits through the CLI; expect **3,000 questions / 30 businesses** and **1,000 questions / 14 businesses**.

## Completion boundary

Update the progress document when these checks pass. Invalid input is reported as an input error; answerability and abstention remain later tasks. T4 requires no downloads, GPU run, new dependencies, or changes to model settings.
