# T8: Load CSV data with an explicit layout

## Summary

Implement single-source CSV loading into DuckDB while preserving source strings and row references.

All 30 released CSVs currently use record 1 as their header and have consistent widths. They contain **851,699 train records** and **243,766 public-test records** after headers. The loader will still require an explicit layout rather than assume those positions.

No model inference or business-answer computation enters T8.

## Loader contract

Add this function in `data_tools.py`:

```python
load_csv(
    connection,
    business_dir,
    inventory,
    source_id,
    *,
    header_rows,
    first_data_row,
)
```

Reuse T7’s source-path and inventory validation through a shared helper. Require a CSV source, a nonempty increasing list of positive header-record numbers, and a first data record after all selected headers. Reject missing headers and layouts with zero columns.

Use the same logical CSV record numbering as T7, including quoted multiline fields and blank records.

The returned metadata contains:

- A deterministic, unused table name such as `raw_001`.
- Schema, row count, source identity, and selected layout.
- Positional columns `c001`, `c002`, etc., with each column’s original labels from the selected header records.

Keep duplicate and empty labels unchanged in metadata. For multiple header records, retain their separate labels; do not forward-fill or invent combined business names.

Create every business column as `VARCHAR`. Add `__source_id VARCHAR` and `__source_row BIGINT` so each loaded record retains its source identity and logical record number. These establish the single-source foundation for T11.

## Loading and failure behavior

Read through strict UTF-8 with optional BOM and comma delimiters, matching T7.

- Preserve leading zeros, whitespace, money/date strings, literal strings such as `"NA"` and `"NULL"`, empty fields, and duplicate records.
- Preserve fully blank records as rows with SQL nulls across the business columns. Explicit empty fields remain empty strings.
- Derive width from the widest selected header. Missing positions in shorter header records remain explicit missing labels.
- Reject nonblank data records whose width differs, reporting the source ID and logical record number.
- Load every record from `first_data_row` through EOF. Do not automatically remove footers, repeated headers, or totals.

Stream in **4,096-record chunks** using `csv.reader`. Insert through temporary pandas registrations and trusted DuckDB `INSERT … SELECT` statements, with explicit column types. Do not use automatic CSV type inference or file-reading SQL functions.

Create and populate the table in one transaction. Late parsing, width, or insertion failures must remove the new table and temporary registrations while preserving previously existing tables. Never overwrite an existing table.

Separate ingestion from transaction ownership so T11 can reuse it inside a future batch transaction. The public function owns its transaction and leaves the caller’s connection open. Close files and unregister temporary frames on every exit path.

## CLI and verification

Add a mutually exclusive, model-free command in `solver.py`:

```sh
.venv/bin/python solver.py --load-csv train/data/biz_101 \
  --source-id S001 --header-rows 1 --first-data-row 2
```

Require the layout flags explicitly and accept them only in this mode. Print metadata, then close the CLI’s temporary in-memory connection. Exit 0 on success, 1 for loading errors, and 2 for invalid arguments. No model configuration is required.

Add focused tests for:

- Titles before headers, multiple header records, duplicate/empty labels, and skipped pre-data records.
- Leading zeros, raw strings, empty fields, blank records, duplicate records, and quoted newlines.
- Missing headers, invalid layouts, ragged records, malformed CSV, source changes, and path boundaries.
- Failure after an earlier chunk, rollback, temporary-registration cleanup, and preservation of existing tables.
- Repeated loads producing distinct tables.
- Loading with DuckDB external access disabled.
- CLI execution without configuration/model initialization.

Run the existing 81 tests plus new tests. Load all 30 released CSVs individually using the observed layout. Compare all loaded values and source-row references against independent CSV iteration, using bounded fetches. Expect the record totals above.
