# T10: Copy SQLite tables through read-only access

## Summary

Implement single-table SQLite loading into DuckDB using trusted Python code.

The released databases contain:

| Split | Database | User tables | Rows |
|---|---|---:|---:|
| Train | `biz_123/pos.sqlite` | 17 | 268,911 |
| Public test | `dev_006/pos.sqlite` | 17 | 302,800 |
| **Total** | | **34** | **571,711** |

Their values include text, integers, and nulls. Preserve actual SQLite value types rather than converting everything according to declared column types.

This checkpoint performs loading and integrity checks only, with no model training or question-answer inference.

## Loader contract

Add in `data_tools.py`:

```python
load_sqlite(connection, business_dir, inventory, source_id)
```

The source ID selects the original database/table through the trusted inventory. No header-layout arguments are needed.

Reuse source validation and deterministic unused table names. Extract shared SQLite schema/ordering helpers from T7 so inspection and loading follow the same row-reference convention.

Return target table/schema/count metadata, original source identity, original column names and declared types, primary-key metadata, ordering information, and `row_reference="ordered_sqlite_record"`.

Use positional business columns `c001`, etc., with DuckDB `VARIANT` storage, plus:

- `__source_id VARCHAR`
- `__source_row BIGINT`: ordinal position in the declared ordering
- `__source_key VARIANT`: the actual rowid or composite primary-key values

These keys identify rows within the input database snapshot. Do not present the ordinal as a physical SQLite row number.

## Read and copy behavior

Open the source using `sqlite3` with URI `mode=ro`, and use a consistent read transaction for metadata and rows. Execute only fixed metadata queries and a quoted table SELECT. Never enable extensions, attach other databases, or execute source DDL/DML.

Preserve T7’s ordering:

- Use an accessible rowid alias for ordinary rowid tables.
- Use declared primary-key columns for `WITHOUT ROWID` tables.
- Reject sources where reliable ordering cannot be established.

Stream through one cursor using **4,096-row `fetchmany` batches**. Preserve integers, real numbers, text, nulls, duplicate business records, and leading-zero strings. Retain declared types as metadata; do not infer dates, normalize money, fill blanks, or deduplicate.

Represent BLOBs using T7’s reversible base64/type encoding. Reuse existing explicit encodings for exceptional values and T9’s VARIANT insertion approach. Include the same text/numeric SQL-casting hint.

Create and populate the DuckDB table atomically. Late read, conversion, or insertion failures must roll back the new table and remove staging registrations while preserving existing tables.

Keep ingestion transaction-neutral internally for T11. The public function requires an idle caller-owned DuckDB connection and leaves it open. Close source connections, cursors, and staging registrations on every exit path. Do not use DuckDB’s SQLite extension or file-reading SQL.

## CLI and tests

Add a mutually exclusive, model-free command in `solver.py`:

```sh
.venv/bin/python solver.py --load-sqlite train/data/biz_123 \
  --source-id S001
```

Share `--source-id` with other loaders, but reject header/layout flags in SQLite mode. Print metadata and close the CLI’s temporary DuckDB connection. Keep exit codes 0/1/2 for success, loading errors, and invalid arguments. No model configuration is required.

Add focused tests for:

- Mixed SQLite storage classes, nulls, leading-zero strings, duplicates, and BLOB encoding.
- Rowid gaps/shadowing, composite primary keys, generated columns, and quoted identifiers.
- Read-only enforcement, consistent source snapshots, and unchanged source bytes.
- Missing/changed sources, wrong formats, and path escapes.
- Late failures, rollback, staging cleanup, connection ownership, and existing-table preservation.
- Model-free CLI behavior and unchanged CSV/Excel behavior.

Run the existing **114 tests** plus new tests.

Load all 34 released tables and compare every canonicalized cell, value type, source ordinal, and source key against an independent read-only SQLite reader using bounded batches. Verify the row totals above, schemas, metadata, cleanup, and database hashes.
