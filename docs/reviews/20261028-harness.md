This is a plan interpretation risk, not an observed runtime bug.

Disposition: preserve the approved behavior. The memory table now separates immutable policy, released facts, question-local working state, per-business raw-table cache and developer-only episode logs. Previous predictions are not promoted into facts. No general memory database or consolidation agent is added. The same rule preserves current-split/as-of semantics and the held-out evaluation boundary.

```text
CLI/batch request -> prepared documents + source catalog
                -> question-local run -> JSON action validation
                -> restricted tool execution -> observation -> repeat
                -> candidate-bound checks -> typed finish
                -> answer / unsupported evidence / bounded abstention

Every stage -> local versioned events
Events + predictions -> development scorer -> diagnosis -> reviewed edit
Frozen release -> offline inference; no edit/consolidation branch
```

Security/access boundaries remain the prior SELECT parser, DuckDB external-access restrictions, host-only file loaders, read-only SQLite, and current-business path checks. Documents/data do not grant execution authority. No networking, remote judge, extra parameter-bearing model or human-intervention branch is added to submitted inference. ## 2. Code quality review

**F2 [P2] (confidence: 8/10), approved T20 and current plan lines 75-79: make useful diagnostics an implementable contract.** Motivating approved text: "Add deadlines, cache cleanup, and traces" and "Failures produce abstentions and useful diagnostics." The approved plan did not enumerate trace attribution fields. An answer-only log would not distinguish a model error from a tool failure or a version change. Runtime behavior is not yet implemented or verified.

Disposition: specify a manifest, structured per-event attribution and the same injectable question runner for fake/recorded and real model actions. Manifest fields identify prompt, tool schemas, code, model, inputs and runtime. Events distinguish context, model, tool, check and finish stages. Replay re-executes tools; it is not claimed as proof of identical fresh-model output. This elaborates existing T15/T20/T21/T27 proof, without a new framework, telemetry service or automatic deployment policy.

The three source boundaries remain explicit. No shared-code extraction is proposed: there are no existing authored callers to prove an extraction benefit. Helpers needed by fake/real adapters belong to the same runtime implementation. Keep error codes, reference scoping and final serialization in the host rather than duplicating them in prompts. The prompt contains business-solving instructions, not a hidden second implementation of the SQL safety gate.
