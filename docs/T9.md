# T9: Load Excel worksheets with an explicit layout

## Summary

Add single-worksheet Excel loading into DuckDB, extending T8’s explicit-layout approach.

The released data contains **176 workbooks and 438 worksheets**: 302 train and 136 public-test worksheets. Layouts include titles, report notes, headers on rows 1–4, and two-row headers. All worksheets lack declared dimensions.

Excel columns will use DuckDB’s existing **`VARIANT` type** to preserve mixed numbers, strings, and Booleans without forcing an entire column to text. This is supported by the pinned runtime and verified locally. [DuckDB documentation](https://duckdb.org/docs/2.0/sql/data_types/variant)

This checkpoint performs loading and integrity checks only—no training or question-answer inference.

## Loader contract

Add in `data_tools.py`:

```python
load_excel(
    connection,
    business_dir,
    inventory,
    source_id,
    *,
    header_rows,
    first_data_row,
)
```

The source ID selects the worksheet through the trusted inventory. Reuse source validation, layout validation, deterministic table naming, and T8’s transaction/cleanup patterns. Preserve T8’s public behavior.

Return table/schema/count/source/layout metadata, original header labels, workbook epoch, and `row_reference="worksheet_row"`.

- Require positive, increasing, unique header rows and a first data row after them.
- Derive column width from the widest selected header row.
- Keep separate labels for multiple headers, including duplicate labels and blank positions. Do not forward-fill merged headings.
- Create positional columns `c001`, etc., as `VARIANT`, plus `__source_id VARCHAR` and `__source_row BIGINT`.
- Include a SQL hint: normalize Excel values with `CAST(c001 AS VARCHAR)` before text parsing; numeric parsing uses `TRY_CAST(CAST(c001 AS VARCHAR) AS DOUBLE)`.

## Loading behavior

Open through an owned file handle using openpyxl read-only mode, preserve formulas, disable external-link retention, and reset worksheet dimensions.

Stream physical worksheet rows through EOF:

- Preserve numbers, strings, Booleans, duplicates, interior blank rows, and continuation rows.
- Pad missing cells within the selected width with SQL nulls.
- Reject nonempty cells beyond that width with worksheet/cell coordinates.
- Keep numeric serial dates numeric and retain epoch metadata.
- Represent date/time objects as ISO text.
- Preserve formulas and Excel errors as tagged objects containing their literal values; never use cached formula results or evaluate formulas. Reuse T7’s explicit encodings for other supported exceptional values.
- Do not remove totals, repeated headers, footers, or business records automatically.

Use **4,096-row chunks**. Encode cell values as JSON-compatible payloads in temporary pandas registrations, then insert through explicit `JSON`-to-`VARIANT` casts. SQL nulls must remain actual nulls, and numeric-looking strings must remain strings. This insertion path must work with external access and extension autoloading disabled.

Create and populate each table atomically. Late parsing, value, width, or insertion failures roll back the new table and remove staging registrations while preserving existing tables. Keep ingestion transaction-neutral internally for T11. The public function requires an idle caller-owned connection and leaves it open.

Close worksheet iterators, workbooks, file handles, and staging registrations on every exit path.

Share layout flags with CSV loading. Print metadata and close the CLI’s temporary connection. Keep exit codes 0/1/2 for success, loading errors, and invalid arguments. No model configuration is required.

- Formula/error preservation and explicit SQL casts.
- Missing headers/sheets, out-of-width values, source/path validation, late rollback, and cleanup.

Keep that manifest outside runtime inference; add no business-ID-specific layout handlers. Load each worksheet and compare every canonicalized cell and physical row reference against an independent streaming reader using bounded fetches.
