# T13: Store complete SQL results and return bounded previews

## Summary

Add question-local result storage in `data_tools.py`. SQL results remain complete outside model context; the model receives a result reference, schema, total row count and explicitly labeled preview.

Use your selected **bounded-RAM approach**, with a provisional **32 MiB budget per question**. No new dependency, CLI mode, model run or answer serializer enters T13.

## Storage and execution APIs

Add:

```python
ResultStore(question_id, *, max_bytes=32 * 1024**2)

execute_sql(
    connection,
    sql,
    *,
    store,
    allowed_tables,
    purpose,
    timeout_seconds=10,
    preview_rows=12,
    preview_bytes=16 * 1024,
)
```

`ResultStore` provides host-only `describe(result_ref)` and `iter_rows(result_ref)`, plus `clear()`, `close()` and context-manager cleanup.

- Each store belongs to one question attempt. References include a unique store identity and cannot resolve in another store, even for the same question ID.
- Preserve query order, duplicate rows, nulls, native value types and complete strings.
- Retain schema columns in order with one-based positions, original names and DuckDB type strings. Duplicate output names remain distinct by position.
- Store SQL, purpose, question identity, schema and total row count with each result.
- `clear()` invalidates existing references; `close()` also prevents further use. Do not evict earlier results automatically.

Read through T12’s `restricted_query` using `fetchmany(4096)`. Store type-preserving chunks as private, protocol-5 pickle bytes in RAM. Only serialize supported native DuckDB return values; never accept serialized input from the model or external files.

Count serialized metadata and row-chunk bytes against the shared 32 MiB budget. This is a stored-payload limit, **not a total process-RSS guarantee**; temporary fetched objects and Python container overhead remain additional memory.

Publish a reference only after complete consumption, preview preparation and successful exit from `restricted_query`. Timeout, permission, conversion, serialization or capacity failures discard the pending result and preserve previous results and budget accounting.

Host retrieval reconstructs native rows from stored chunks without rerunning SQL. Mutating retrieved nested values must not modify the stored result.

## Preview behavior

Return:

- Result reference and complete ordered schema.
- Total stored row count.
- Leading preview rows and their count.
- Explicit `is_preview` and `preview_truncated` flags.
- Stored-payload byte count.

Default to at most **12 complete rows** and **16 KiB for the complete JSON observation**, measured with strict UTF-8 JSON serialization.

- Remove whole trailing preview rows until the observation fits. Never shorten cell values or omit schema columns.
- If the first row cannot fit, return an empty preview with an explicit reason and an instruction to narrow the SQL projection.
- If metadata alone cannot fit, reject the operation without publishing its result.
- Zero-row results remain valid and retain their schema.

Encode preview values separately from stored values. Preserve JSON primitives and recursively handle nested values; use explicit markers for decimals, dates/times, durations, UUIDs, binary values, nonfinite numbers and maps with non-string keys. Avoid lossy numeric conversion or implicit stringification.

Unsupported values produce actionable errors. Submission-type validation, rounding and rejection of invalid final-answer values remain T18.
