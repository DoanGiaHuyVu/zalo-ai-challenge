# T15: Run the bounded loop with a fake model

## Summary

Keep your selected **test-only finish callback**. The default path accepts abstention but rejects computed and unanswerable finishes until T17–T19 provide production validation.

Implement three small checkpoints: runner/dispatch, context admission, then scripted replay and verification. No real-model inference or new dependency enters T15.

## Runner and tool dispatch

Add in `solver.py`:

```python
run_question(
    split_root,
    question,
    *,
    action_provider,
    token_counter,
    config,
    finish_handler=None,
)
```

- `action_provider(messages, *, first_action)` returns action JSON text or a dictionary.
- `token_counter(messages)` supplies exact prompt-token counts; tests may inject a deterministic counter.
- An optional trusted `finish_handler` receives the action and current question/store/result-role/source-catalog context, returning a submission record or rejecting with `ValueError`.

The runner owns a fresh secured connection, prepared business context, `ResultStore`, source catalog, result-role registry and trajectory. Close resources on every exit. Business-cache reuse remains T20.

Count every provider invocation toward the existing **eight-turn cap**, including malformed responses and rejected finish attempts. Accept a valid finish on turn eight; never invoke a ninth turn. Keep the first-action phase until an action passes structural validation, then retain its task specification.

Dispatch only:

- `inspect` → `inspect_sources`.
- `load` → `load_sources`; register metadata only after successful loading.
- `sql` → `execute_sql`, allowing only `calendar` and successfully loaded tables.
- `finish` → immediate abstention or the injected finish handler.

Before check SQL, require its candidate reference to resolve to a current-question compute result. Record compute/check roles and candidate associations; do not interpret diagnostic pass values yet.

Known action/tool errors become observations for repair. Provider exhaustion, fatal backend failures, context exhaustion or turn exhaustion produce abstention. Invalid question inputs fail clearly before provider invocation. Tool failures never automatically become `unanswerable`.

Check the configured local question deadline between operations and pass remaining time into the SQL timeout. Process-level interruption of blocked providers/loaders remains T20.

Return the submission, stop reason, turns used and complete host-side trajectory. Handler rejection permits another turn; without a handler, computed/unanswerable finishes return an explicit “validation unavailable” observation.

- Accepted task specification.

- Stored-result references, schemas, counts and roles.
- Compact action history and recent observations.

Keep full source catalogs, results and trajectory outside model context. Avoid repeating each monthly source’s identical schema.

Before every provider call, require:

```text
exact prompt tokens + 1,024 output tokens ≤ 16,384
```

When necessary, compact deterministically:

1. Remove older observation payloads while retaining action outcomes and references.
2. Reduce recent inspection/SQL previews using complete rows.
3. If complete mandatory documents and remaining state still cannot fit, abstain without calling the provider.

Mark all preview omissions explicitly. Preserve original source-row references and pagination information so omitted inspection rows are not mistaken for nonexistent rows. Never shorten document text, column labels, stored results or required schemas.

Record token counts and compaction decisions in the trajectory. This makes T14’s narrow remaining margin an enforced runtime constraint.
